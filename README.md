# 중개메이트

여러 중개사가 매물과 고객을 함께 보는 부동산 사무소를 위한 업무 도구입니다.

- **지도**: 매물이 고객과의 거래에서 어느 단계에 있는지(소개 → 방문 → 협의 → 계약 → 완료)를 색과 칸으로 보여 줍니다.
- **고객 자료**: 비교표와 문의 답변을 근거 출처가 달린 문서로 만들고, 승인한 판만 인쇄·PDF나 링크로 고객에게 보냅니다.

구성은 **웹 화면 + FastAPI 애플리케이션 1개 + PostgreSQL(pgvector) 1개**입니다. 캐시, 메시지 큐, 별도 벡터 DB는 두지 않습니다.
설계 배경은 `docs/redesign.md`, API 계약은 `docs/API.md`, 클릭 시안은 `docs/prototype/index.html`에 있습니다.

## 실행 (Docker)

```bash
cp .env.example .env          # 선택: ANTHROPIC_API_KEY, DATA_GO_KR_SERVICE_KEY, JWT_SECRET
docker compose up -d --build
```

### 공공데이터 API 키

공공데이터포털에서 승인된 API들은 `.env`의 `DATA_GO_KR_SERVICE_KEY` **한 값**을 함께 사용합니다. 포털에 표시되는 Encoding 키와 Decoding 키 중 어느 쪽이든 넣을 수 있으며, 키를 코드나 Git에 커밋하지 않습니다.

```bash
cp .env.example .env
# .env의 DATA_GO_KR_SERVICE_KEY= 뒤에 본인의 키 입력
python scripts/check_public_data_config.py
```

진단 명령은 키 값을 출력하지 않고 `SET`/`MISSING`만 표시합니다. 키가 `SET`이어도 아래 데이터셋은 각각 공공데이터포털 마이페이지에서 활용신청 승인을 받아야 합니다.

- `15126468` 아파트 매매 실거래가
- `15126474` 아파트 전월세 실거래가
- `15058453` 공동주택 기본정보(K-apt)
- `15134735` 건축HUB 건축물대장
- `15098554` TAGO 지하철정보

다음 연동은 공공데이터포털 공통 키로 대체되지 않습니다.

- 현행법령 본문(`15057358`): 국가법령정보 공동활용에서 발급받은 기관 ID를 `LAW_GO_KR_OC`에 입력
- VWorld 지도·공간정보(`15058805`): VWorld 개발자센터의 `VWORLD_API_KEY`와 신청 시 등록한 `VWORLD_API_DOMAIN`을 함께 입력
- 도로명주소 검색·좌표: 도로명주소 개발자센터에서 발급받은 `JUSO_API_KEY` 입력

현재 기본 지도(OpenStreetMap)와 핵심 매물 업무는 이 별도 설정이 없어도 동작합니다.

- 작업 화면: http://localhost:8000/app.html (http://localhost:8000 도 같은 곳으로 이동)
- API 문서(OpenAPI): http://localhost:8000/docs
- 고객용 공개 링크: `http://localhost:8000/r/{token}` (승인 후 "링크로 보내기"로 만들어지며 7일 유효)

## 화면

| 메뉴 | 하는 일 |
|---|---|
| **상단 질문** (모든 화면, `/` 키) | 누르면 뒤가 흐려지고 질문 창이 위에서 내려옵니다(바깥을 누르거나 Esc로 닫힘). "마포구 8억 이하 59㎡ 학교 가까운 집", "생애최초 지원 받을 수 있는 아파트"처럼 묻습니다. 지도 왼쪽에 **맞는 매물**(맞는 이유·차이 나는 조건)과 **답변**(문장마다 출처 각주)이 나오고, 지도에서 맞는 매물만 강조됩니다. 찾은 조건을 눌러 빼고 다시 찾거나, [고객 자료로 만들기]로 이어집니다 |
| **Hood AI** (지도 옆 메뉴) | 마우스를 올리면 보고서·사용량·설정 목록, 누르면 전용 검색 화면. 대화처럼 이어 묻기("그중 7억 이하만"), 답마다 작은 지도와 맞는 매물, 이전 대화 목록. 보고서(고객 자료 상태별 목록), 사용량(질문 수·사람별·쓴 출처), 설정(답변에 쓸 자료·매물 수·월 한도, 관리자) |
| **Ask Hood** (이름 왼쪽) | 어느 화면에서든 오른쪽 패널로 바로 묻기. 시계 아이콘으로 이전 대화를 불러와 이어 묻기 |
| **지도** | 단계별 색 핀(칸 = 진행 정도, 숫자 = 연결된 고객 수), 내 매물/사무소 전체, 단계 필터. 핀을 누르면 왼쪽에 거래(단계 변경), **확인할 사항**(출처 연결), **현장 메모**(사무소 누구나 작성, 질문 검색에 쓰임), 매물 정보. 지도를 눌러 매물 등록 |
| **거래** | 단계별 보드, 내 거래/사무소 전체, 단계 이동 |
| **고객** | 찾는 조건, 거래, 고객 자료, 상담 기록. [조건에 맞는 매물 지도에서 보기] [비교표 작성] [문의 답변 작성] |
| **자료실** | 법령·정책·사무소 문서·기사 검색, 원문 확인, 고객 문의 답변에 인용, [이 내용으로 질문하기], **[자료 추가]**(중개사가 단지 정보·학구도 확인 결과 등을 직접 적으면 바로 검색 근거가 됨), (관리자) 파일 등록 |
| **고객 자료** | A4 문서. 본문 각주 → 출처 목록. 작성 → 검토 → 승인 → 인쇄/PDF·링크 |

### 문서 근거 검색(RAG)을 쓰는 곳

0. **질문 검색**: 질문에서 조건(지역·가격·면적·역 거리·평형)과 바라는 점(학교·공원·조용한·남향 등)을 뽑아 매물을 SQL로 거르고, 바라는 점은 매물 설명·현장 메모·단지 이름이 나오는 사무소 자료에서 찾아 순위를 매깁니다. 법령·정책·기사는 문서 검색 + 근거 게이트로 붙이고, 실거래가는 SQL로 붙입니다. 조건을 모두 만족하는 매물이 없으면 조건을 조금 넓혀 "조건에 가까운 매물"과 차이를 보여 줍니다. (`backend/app/assistant.py`)
1. **매물 › 확인할 사항**: 매물의 가격·지역·거래 단계에 맞는 항목을 자료실 문서에서 찾아 출처와 함께 보여 줍니다. 예를 들어 계약 단계가 되면 "30일 이내 거래 신고"가 거래신고법 조문과 함께 나타납니다.
2. **고객 자료**: 문장마다 출처 각주를 답니다. 근거가 없는 내용은 본문에 넣지 않고 "추가로 확인할 사항"으로 보냅니다.
3. **자료실**: 직접 검색합니다. 중개사가 추가한 사무소 자료와 현장 메모도 같은 근거로 쓰입니다.

자료 간 불일치(예: 기사와 공식 안내의 시행일 차이)나 시행 전 정책은 근거 게이트가 결정론적으로 표시합니다.

### 권한 (기본값)

- 사무소 전원이 모든 매물·고객·거래를 볼 수 있습니다.
- 거래 단계 변경은 **거래 담당·매물 담당 중개사나 관리자**만 할 수 있습니다.
- 매물 수정·거래 종료는 **매물 담당이나 관리자**만 할 수 있습니다.
- 고객 자료 승인은 **고객 담당이나 관리자**만 할 수 있습니다.
- 한 매물이 계약 단계가 되어도 같은 매물의 다른 거래는 **자동으로 무산 처리하지 않고** 안내만 합니다.

## 테스트

```bash
docker compose up -d db

docker compose down -v && docker compose up -d --build   # 깨끗한 시드 데이터로 다시 시작

```

## 설계 원칙과 구현

| 원칙 | 구현 |
|---|---|
| 매물은 데이터로 비교 | 매물·실거래가는 SQL로 조회하며 벡터화하지 않음 |
| 설명은 근거와 연결 | 본문 문장마다 출처 id. 없는 id는 제거하고, 출처 없는 주장은 "추가로 확인할 사항"으로 보냄 |
| 모르면 단정하지 않음 | 공식 근거 없음·기사만 있음·시행 전·자료 간 불일치를 근거 게이트가 표시 |
| 승인은 사람이 | 작성 → 검토 → 승인(고객 담당) → 전달. 승인 후 수정 불가, 승인본만 인쇄·공유 |
| 근거 우선순위 | 법령 > 공식 정책 > 사무소 문서 > 기사(보조) |
| 검색 전에 차단 | SQL `WHERE`에서 사무소·지역·기준일을 먼저 거름 |
| 개인정보 | LLM 프롬프트·감사 기록에 고객 이름·연락처를 넣지 않음 |
| 장애 시 강등 | LLM 장애 시 고객 자료 작성만 503. 지도·거래·자료실은 정상 |
| 운영 기록 | `X-Request-ID`, 단계 변경·승인·공유·열람을 감사 기록과 고객 상담 기록에 남김 |

## LLM / 임베딩

- `ANTHROPIC_API_KEY`가 없으면 문장 틀에 매물 데이터와 문서 조각을 채우는 **규칙 기반 작성기**로 동작합니다.
- 키를 설정하면 Claude(`LLM_MODEL`, 기본 `claude-opus-5-5`)가 의견 문단을 씁니다. 이때도 출처 검증과 근거 게이트 항목은 서버가 결정론적으로 덧붙입니다.
- 임베딩은 MVP용 해싱 임베딩입니다. 바꾸려면 `embedding.py`를 교체하고 문서를 다시 인덱싱합니다.
