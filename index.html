        공개데이터 활용 설계

        공개데이터는
        이렇게 씁니다

        가격·단지·건축물 정보는 구조화 데이터로 비교합니다. 이 공개데이터 목록에서는 법령 원문을 RAG로 처리하며, 별도의 공식 정책 문서·이용이 허용된 기사·권한 있는 사무소 문서도 RAG 대상에 포함합니다. 모든 결과에는 제공기관과 기준일을 남깁니다.

        01

        아파트 실거래가

        국토교통부 · 매매 / 전월세

        매매 공식 데이터 전월세 공식 데이터
        구조화 DB

        지역·계약월·면적별 실제 신고가격을 비교하고 가격 흐름의 참고 기준으로 사용합니다.

        한계 과거 신고 거래입니다. 현재 판매 매물, 호가, 거래 가능 상태가 아닙니다.

        02

        공동주택 기본정보

        국토교통부 · K-apt

        공식 데이터 보기
        구조화 DB

        단지 주소, 세대수, 동수, 난방·관리방식과 주변 편의시설을 후보 비교표에 연결합니다.

        기준 제공기관 갱신일과 수집 시각을 함께 표시합니다.

        03

        건축물대장

        국토교통부 · 건축HUB

        공식 데이터 보기
        구조화 DB

        용도, 구조, 층·면적, 사용승인 정보를 조회해 매물 설명의 기초 사실을 검증합니다.

        한계 월간 갱신 자료이므로 조회일과 기준일이 다를 수 있습니다.

        04

        주소·공간정보

        행정안전부 도로명주소 · 국토교통부 공간정보

        도로명주소 API WMS/WFS 공식 데이터
        지도 계층

        주소를 표준화하고 좌표·행정경계와 연결해 후보 위치와 주변 환경을 지도에 표시합니다.

        이용조건 공간정보 WMS/WFS는 출처표시가 필요한 공공저작물 제1유형입니다.

        05

        현행법령 본문

        법제처 · 국가법령정보

        공식 데이터 보기
        RAG 근거

        조문, 시행일, 개정 이력을 청크 단위로 검색해 법령 질문의 1차 근거로 사용합니다. 정책 질문은 발행기관의 공식 정책 문서를 별도 근거로 사용합니다.

        원칙 법률 해석을 확정하지 않으며 적용 대상·지역·시점이 불명확하면 확인 불가로 남깁니다.

        06

        지하철 정보

        국토교통부 · TAGO

        공식 데이터 보기
        구조화 DB

        역·출구·주변시설을 주소 좌표와 결합해 역세권 조건과 생활 편의 비교에 활용합니다.

        한계 실제 도보시간은 별도 경로 계산 결과와 기준 시각을 함께 보여야 합니다.

        데이터 경계

        공개데이터가
        말해주지 않는 것

        현재 매물은 별도 권한이 필요합니다

        실거래가는 과거 신고정보입니다. 현재 후보·호가·거래 가능 상태는 제휴 매물 API, 사무소 내부 DB 또는 중개사가 업로드한 CSV만 사용합니다. 무단 크롤링은 사용하지 않습니다.

        근거 우선순위

        1. 1

          법령·공식 정책 원문 적용 여부와 시행일의 1차 근거

        2. 2

          허용된 사무소 문서 상담 절차와 내부 기준

        3. 3

          뉴스 검색 결과 시장 맥락을 설명하는 보조 자료이며 법적·정책 사실의 1차 근거로 사용하지 않음

        RAG 구성 설계

        세 종류의 데이터를
        한 답변으로 연결합니다

        정확한 수치와 매물은 구조화 검색으로 확인하고, 법령·정책·사무소 문서는 RAG로 근거를 찾습니다. 고객 조건은 현재 상담 문맥으로만 결합하며 공용 벡터 인덱스에 저장하지 않습니다.

        A

        구조화 사실

        실거래가, K-apt, 건축물대장, 주소·교통, 현재 매물, 가격 이력

        SQL·공간검색 필터·정렬·수치 계산에 사용하며 벡터화하지 않음
        B

        문서 근거

        현행법령, 공식 정책·공고·FAQ, 권한 있는 사무소 문서, 허용 뉴스

        하이브리드 RAG 키워드+벡터 검색, 재정렬, 주장별 인용 검증
        C

        상담 문맥

        예산·면적·입지·생활 선호, 관심·제외 후보, 현재 상담 기록

        세션 주입 사무소 권한 안에서만 사용하며 공용 인덱스 저장 금지
        구조화 사실+문서 근거+상담 문맥=근거가 연결된 AI 초안

        검색 전략

        기능마다 다른 검색 순서

        /ask

        질문 유형·지역·대상·기준일을 먼저 파악하고 관련 인덱스에서 근거를 찾습니다. 공식 근거가 없으면 뉴스만으로 정책 적용 여부를 답하지 않습니다.

        /advise

        구조화 DB에서 후보 2~5개를 먼저 확정한 뒤 후보별 정책·법령·확인 절차를 검색합니다. RAG는 추천 점수를 만들지 않고 이유와 확인 사항만 씁니다.

        근거 정책

        권위와 최신성을 함께 봅니다

        1. 1현행 법령
        2. 2발행기관의 공식 정책 문서
        3. 3권한 있는 사무소 문서
        4. 4허용된 뉴스 보조자료

        보안과 운영

        검색하기 전에 차단합니다

        • 검색 전에 사무소 tenant와 문서 ACL 적용
        • 고객 개인정보는 공용 벡터 인덱스에 저장 금지
        • 문서 속 명령은 데이터로 취급해 실행하지 않음
        • 기사 본문은 이용권한 없이는 저장·임베딩하지 않음
        • 문서 삭제·권한 변경 시 조각과 캐시까지 삭제 전파

        선택적 MCP 실험

        필수 기능이 끝난 뒤
        연결 방식을 비교합니다

        MVP는 FastAPI의 직접 API 어댑터로 완성합니다. 일정에 여유가 있을 때만 읽기 전용 공공데이터 MCP Server 하나를 만들어 같은 결과를 반환하는지 비교합니다.

        Host 중개메이트 AI 오케스트레이터 업무 권한·RAG 계획·최종 판단을 소유
        Client · Policy Gateway 허용목록 → 권한 → 스키마 → 시간초과 → 감사 브라우저가 아닌 FastAPI 내부에서 서버별 Client 세션으로 실행
        PoC Server 01읽기 전용 공공데이터직접 API 어댑터와 결과·지연·오류를 비교
        읽기 전용

        쓰기 Tool과 서버 주도 capability는 제공하지 않습니다. 출처·기준일·이용조건이 없으면 근거로 사용하지 않습니다.

        MCP 없이 동작

        장애 시 직접 API 어댑터를 사용합니다. MCP를 구현하지 않아도 모든 MVP 기능이 완료되어야 합니다.

        선택 범위: 시간이 남을 때 읽기 전용 MCP Server 1개와 조회 Tool 1개만 비교 구현합니다.

        서버 주도의 모델 호출·사용자 추가 질문·파일 접근 capability는 MVP에서 제공하지 않습니다.

        비동기 자료 경로

        운영 중인 검색을 건드리지 않고 갱신합니다

        1. 외부 출처공개 API · 공식/내부 문서
        2. 수집 작업자원본 보관 · 재시도 · 중복 방지

        4. 후보 버전정규화 DB · 새 벡터 인덱스
        5. 전환골든 Q&A 통과 후 원자 교체
        보안 경계

        클라이언트의 tenant 값을 믿지 않습니다

        인증 결과로 사무소를 확정하고 DB와 벡터 검색 전에 같은 ACL을 적용합니다. 고객 개인정보는 공용 벡터·로그·분석 이벤트에 남기지 않습니다.
