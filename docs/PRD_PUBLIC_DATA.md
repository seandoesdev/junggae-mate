# 공공데이터 기반 부동산 정보 기능 PRD

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 제품 | Roomio / 중개메이트 |
| 문서 버전 | v0.1 |
| 작성일 | 2026-11-02 |
| 상태 | 구현 제안 |
| 대상 사용자 | 부동산 사무소의 중개사와 관리자 |
| 연관 화면 | 매물 지도·상세, 고객, 질문 검색, 고객 자료, 관리자 데이터 수집 |

이 문서는 공공데이터포털에서 활용신청한 국토교통부 API 5종을 Roomio의 기존 업무 흐름에 어떻게 적용할지 정의한다. 공공데이터 자체를 별도 메뉴로 나열하는 것이 아니라, 중개사가 매물을 확인하고 고객에게 설명하는 시점에 공식 근거로 제공하는 것이 핵심이다.

### 1.1 현재 구현 기준선

- 아파트 매매 실거래가는 관리자 수집 API, 저장 모델, 매물·질문·비교자료 조회 흐름에 연결돼 있다.
- 전월세·K-apt·건축물대장·지하철은 공통 서비스키로 호출할 수 있는 어댑터와 명세 등록까지만 준비돼 있다.
- 나머지 4종의 제품 기능에는 저장 모델, 업무 API, 매물 연결 로직과 UI가 추가로 필요하다.
- K-apt 상세정보와 TAGO 출구·연계교통·편의시설은 현재 기본 operation에 포함되지 않으며 각 상세 operation 어댑터를 구현한 뒤 사용할 수 있다.

## 2. 배경과 문제 정의

현재 Roomio는 매물·고객·거래 단계를 한곳에서 관리하고, 실거래가와 문서 근거를 이용해 고객 비교자료를 만든다. 그러나 다음 정보는 중개사가 외부 사이트에서 따로 확인하거나 직접 입력해야 한다.

- 매물 호가와 비교할 최근 매매·전월세 신고 사례
- 단지 기본정보와 관리 관련 객관적 사실
- 건축물대장상 용도·구조·층·면적 등 확인 정보
- 고객이 중요하게 보는 지하철역 및 출구 관련 정보
- 각 정보가 언제, 어느 기관에서 조회됐는지에 대한 근거

이 때문에 매물 등록과 고객 자료 작성에 시간이 걸리고, 같은 정보를 여러 중개사가 반복 조회하며, 수기 입력 오류가 생긴다. 공공데이터 연동으로 반복 조회를 줄이되, 공식 데이터가 현재 현장 상태나 법적 판단을 완전히 대체하지 않는다는 점을 명확히 해야 한다.

## 3. 목표와 비목표

### 3.1 목표

1. 매물 상세에서 단지·건축물·교통 정보를 자동 보강한다.
2. 매매와 전월세 고객에게 거래 유형에 맞는 최근 신고 사례를 제공한다.
3. 고객 비교자료와 질문 답변에 공공데이터 출처와 조회 기준일을 자동 첨부한다.
4. 데이터가 없거나 오래됐거나 매물과 정확히 연결되지 않은 경우 이를 숨기지 않고 표시한다.
5. 외부 API 장애가 있어도 매물·고객·거래의 핵심 업무는 계속 사용할 수 있게 한다.

### 3.2 비목표

- 공공데이터만으로 신규 매물을 자동 생성하거나 광고 매물을 수집하지 않는다.
- 미래 가격 예측, 적정가 보장, 투자 추천을 제공하지 않는다.
- 건축물대장이나 단지정보를 법적 확인·현장 확인의 대체물로 표현하지 않는다.
- TAGO API 범위에 없는 실시간 열차 도착정보나 정확한 도보 경로를 추정하지 않는다.
- 이번 범위에서 VWorld, 도로명주소, 국가법령정보의 별도 키 연동은 구현하지 않는다.

## 4. 사용자와 핵심 사용 사례

### 4.1 중개사

- 매물을 등록하거나 열었을 때 주소·단지명을 바탕으로 공식 정보를 불러온다.
- 매도 호가와 최근 동일·유사 면적 매매 신고가를 비교한다.
- 전세·월세 고객에게 최근 보증금·월세 신고 사례를 보여 준다.
- 고객 조건에 맞는 매물을 고를 때 단지 정보와 지하철 접근 정보를 함께 본다.
- 비교표를 만들 때 공식 정보를 다시 복사하지 않고 자동으로 포함한다.

### 4.2 관리자

- 지역과 기간을 지정해 공공데이터를 수집·갱신한다.
- 마지막 성공 시각, 수집 건수, 오류 사유와 재시도 상태를 확인한다.
- 매물과 공공데이터가 잘못 연결된 경우 자동 연결을 해제하거나 올바른 대상을 지정한다.

### 4.3 고객

- 승인된 비교자료에서 호가와 과거 신고가를 구분해 본다.
- 단지·건축물·교통 정보의 출처와 기준일을 확인한다.
- 자료가 없거나 추가 확인이 필요한 항목을 명확히 인지한다.

## 6. 기능 요구사항

### FR-1. 공공데이터 수집과 갱신

- 관리자는 지역 코드와 대상 월을 지정해 매매·전월세 데이터를 수동 수집할 수 있어야 한다.
- MVP는 관리자 수동 수집을 제공한다. 자동 증분 수집은 실행 주체를 결정한 뒤 별도 단계에서 추가한다.
- API 페이지네이션을 끝까지 처리하고 같은 원천 거래의 중복 저장을 방지해야 한다.
- 취소·해제된 매매 계약은 현재 유효 사례의 통계에서 제외하되, 추후 감사가 필요하면 원천 상태를 별도로 보관할 수 있어야 한다.
- 실패한 수집은 오류 종류, 대상 데이터셋, 지역·기간, 발생 시각을 남겨야 한다.

### FR-2. 매매 실거래 근거

- 매물 상세에 같은 단지와 유사 전용면적의 최근 거래를 최신순으로 표시해야 한다.
- 기본 집계 기간은 최근 12개월로 하고, 거래가 부족하면 최대 24개월까지 확장했음을 표시해야 한다.
- 중위 거래가, 최저·최고 거래가, 거래 건수를 제공해야 한다.
- 현재 매물 호가와 실거래가의 차이를 숫자로 보여 줄 수 있으나, 적정가 여부를 판단하는 문구는 사용하지 않는다.
- 층·면적·계약일·해제 여부 등 비교에 중요한 원천 필드를 보존해야 한다.

### FR-3. 전월세 실거래 근거

- 고객의 거래 유형이 전세이면 보증금 사례를, 월세이면 보증금과 월세를 분리해 표시해야 한다.
- 전세와 월세를 하나의 가격 통계로 합치지 않는다.
- 계약갱신 여부 등 API가 제공하는 구분값이 있으면 원문 의미를 보존해 표시해야 한다.
- 매매 사례와 마찬가지로 단지·유사 면적·기간 기준을 화면에 표시해야 한다.

### FR-4. 단지 기본정보 보강

- 매물의 단지와 K-apt 단지코드를 연결하고 연결 근거를 저장해야 한다.
- 자동 연결은 주소와 단지명 등 복수 조건을 사용하며, 후보가 여러 개면 중개사 확인을 요청해야 한다.
- 기본 operation이 제공하는 단지정보를 매물 상세의 `공식 단지정보` 영역에 표시해야 한다. 주차 등 세부정보는 K-apt 상세 operation 어댑터를 추가한 뒤 노출한다.
- 중개사가 직접 입력한 값과 공공데이터 값이 다르면 덮어쓰지 않고 나란히 보여 주며 확인 대상으로 표시해야 한다.

### FR-5. 건축물대장 확인정보

- 주소에서 시군구코드·법정동코드와 건물 식별정보를 얻은 뒤 표제부를 조회해야 한다.
- 매물과 연결된 건축물의 주용도, 구조, 층, 연면적 등 제공 가능한 필드를 표시해야 한다.
- 조회 후보가 여러 개인 집합건물은 자동 확정하지 않고 동·호 또는 관리번호 확인을 요구해야 한다.
- 공공데이터 값은 `건축물대장 조회정보`로 표시하며 위반건축물 여부 등 법적·현장 확인이 필요한 사항은 별도 확인 문구를 제공해야 한다.

### FR-6. 지하철 정보 보강

- 매물에 저장된 역명을 기준으로 TAGO 역 검색 결과를 연결해야 한다.
- 동명 역이나 노선이 여러 개인 경우 노선을 포함해 중개사가 선택할 수 있어야 한다.
- 기본 역 검색 결과를 우선 표시한다. 출구·연계교통·편의시설은 해당 TAGO operation 어댑터를 추가한 뒤 실제 응답이 제공하는 정보만 표시한다.
- 역까지 도보 시간은 중개사 입력값을 유지하며, TAGO 데이터만으로 도보 시간을 새로 계산하지 않는다.

### FR-7. 고객 매칭과 질문 검색 반영

- 매매·전세·월세 유형에 맞는 거래 근거를 고객 조건 매칭 결과에 붙여야 한다.
- 질문 검색은 공공데이터의 구조화 값을 SQL로 조회하고 문서 RAG와 혼합 저장하지 않아야 한다.
- 검색 답변의 각 공공데이터 사실은 추적 가능한 출처 ID를 가져야 한다.
- 정보가 없으면 추정 답변을 만들지 않고 `자료 없음` 또는 `추가 확인 필요`로 반환해야 한다.

### FR-8. 고객 비교자료 반영

- 비교표에는 매물별 최근 거래 근거, 공식 단지정보, 건축물 확인정보, 교통정보 중 확인된 항목만 포함해야 한다.
- 고객 자료의 출처 목록에서 데이터셋명, 제공기관, 기준일을 확인할 수 있어야 한다.
- `과거 신고 거래이며 현재 호가가 아님`, `공공데이터 조회 결과로 현장·공부 확인을 대체하지 않음`을 명시해야 한다.
- 자료 승인 후에는 데이터가 갱신돼도 승인본 내용을 자동 변경하지 않고 새 버전을 만들 때만 반영한다.

### FR-9. 관리 화면

- 데이터셋별 `정상`, `일부 실패`, `인증 오류`, `미설정` 상태를 표시해야 한다.
- 키 값은 어떤 화면과 로그에서도 출력하지 않는다.
- 마지막 성공 시각, 마지막 시도 시각, 수집 범위, 신규·중복·제외 건수를 확인할 수 있어야 한다.
- 관리자는 실패 작업을 같은 조건으로 재시도할 수 있어야 한다.

## 7. 사용자 흐름

### 7.1 매물 등록·확인

1. 중개사가 매물을 등록하고 주소와 단지명을 입력한다.
2. 시스템이 법정동 코드 기준정보와 주소 파서를 이용해 지역 식별값을 만들고, K-apt·건축물대장·지하철 후보를 조회한다.
3. 일치 대상이 하나면 자동 연결하고, 복수이면 선택 창을 표시한다.
4. 중개사가 확인한 연결 결과를 저장한다.
5. 매물 상세에 `실거래`, `공식 단지정보`, `건축물대장 조회정보`, `교통정보`를 표시한다.

### 7.2 고객에게 매물 비교자료 제공

1. 중개사가 고객 화면에서 1~5개 매물을 선택해 비교표를 작성한다.
2. 시스템이 승인본 생성 시점의 공공데이터 스냅샷을 포함한다.
3. 정보가 충돌하거나 연결이 불확실한 항목은 `추가로 확인할 사항`으로 분리한다.
4. 고객 담당자가 내용을 검토하고 승인한다.
5. 고객은 인쇄물·PDF·링크에서 출처와 기준일을 함께 확인한다.

### 7.3 관리자 데이터 갱신

1. 관리자가 지역·기간·데이터셋을 선택한다.
2. 시스템이 예상 호출 범위를 보여 주고 수집을 시작한다.
3. 완료 후 신규·중복·제외·실패 건수를 요약한다.
4. 일부 실패 시 성공한 데이터는 유지하고 실패 범위만 재시도한다.

## 8. 데이터 및 시스템 요구사항

### 8.1 저장 모델

기존 `apt_trades`는 매매 전용이므로 전월세를 억지로 섞지 않는다. 구현 시 다음 논리 모델을 추가한다.

| 모델 | 주요 필드 |
|---|---|
| `apt_rent_trades` | 지역코드, 단지명, 면적, 층, 계약일, 보증금, 월세, 계약유형, 갱신 관련 원천값, 출처, 수집시각 |
| `apartment_complexes` | K-apt 코드, 단지명, 주소, 기본정보 JSON, 원천 갱신일, 수집시각 |
| `building_register_snapshots` | 건물 식별키, 주소 코드, 표제부 원천 JSON, 수집시각 |
| `subway_stations` | 역 식별값, 역명, 노선, 출구·연계정보 JSON, 수집시각 |
| `listing_public_data_links` | 매물, 데이터 종류, 원천 식별키, 연결 방식, 신뢰 상태, 확인자, 확인시각 |
| `public_data_sync_runs` | 데이터셋, 요청 범위, 상태, 건수, 오류 요약, 시작·종료시각 |

원천 필드가 바뀌어도 재처리할 수 있도록 정규화 필드와 원천 응답의 필요한 부분을 함께 보존한다. 고객 자료에는 조회 결과를 직접 참조하기보다 승인 시점의 스냅샷과 출처를 저장한다.

공공 원천 데이터는 사무소 간 공유 가능한 전역 데이터로 저장할 수 있다. 매물과 원천 데이터의 연결, 중개사의 수동 확정, 동기화 작업 실행 권한과 감사 기록은 반드시 `tenant_id`로 격리하고 관리자 권한을 적용한다.

### 8.2 식별과 연결 원칙

- 실거래: 법정동 지역코드 + 단지명 + 전용면적 + 계약일 등 원천 식별 조합
- K-apt: K-apt 단지코드를 내부 대표 식별자로 사용
- 건축물대장: 시군구·법정동 코드와 본번·부번, API가 제공하는 건물 식별값 사용
- 지하철: 역명만으로 확정하지 않고 노선 등 식별값 병행
- 문자열 유사도만으로 연결한 결과는 `검토 필요` 상태로 저장

K-apt·건축물대장 연결을 시작하기 전에 다음 탐색 기반을 구현한다.

- 전국 법정동 코드 정적 기준정보와 갱신 절차
- 도로명주소 문자열에서 시군구·법정동·본번·부번을 분리하는 주소 파서
- K-apt 단지코드 목록·검색 operation 어댑터 또는 관리자의 수동 단지코드 연결 화면
- 주소 파싱이 실패하거나 후보가 복수일 때 자동 확정하지 않는 검토 흐름

### 8.3 갱신 정책 초안

| 데이터 | 기본 갱신 |
|---|---|
| 매매·전월세 실거래 | MVP는 관리자 수동 수집. 자동화 결정 후 최근 월은 매일 증분, 과거 월은 요청 시 재수집 |
| K-apt 단지정보 | 30일마다 또는 매물 연결 시 오래된 경우 |
| 건축물대장 | 매물 연결 시 및 고객 자료 생성 전 30일 이상 경과 시 확인 |
| 지하철정보 | 90일마다 또는 역 연결 시 |

호출량 제한과 실제 운영 비용을 확인한 뒤 주기를 조정할 수 있어야 한다.

예약 수집은 현재 구조에 없는 Redis·Celery를 도입하지 않는다. OS 스케줄러, 외부 cron 또는 단일 앱 내 스케줄러 중 하나를 ADR로 결정한 뒤 활성화한다.

## 9. UX 요구사항

- 공공데이터는 별도 `AI 정보`가 아니라 매물 상세와 비교표의 업무 정보로 표시한다.
- 출처는 접을 수 있지만 한 번의 동작으로 데이터셋명과 기준일을 볼 수 있어야 한다.
- `중개사 입력`, `공공데이터`, `계산값`을 시각적으로 구분하되 색만 사용하지 않는다.
- `자료 없음`, `연결 후보`, `검토 필요`, `오래된 자료` 상태를 동일한 용어로 일관되게 사용한다.
- 숫자는 원천 단위와 내부 단위를 수집 경계에서 검증한다. 현재 내부 금액 표준인 만원 단위를 유지하고 화면에서 만원·억원 표기를 제공한다. 원 단위 전환이 필요하면 데이터 마이그레이션을 별도 과제로 수행한다.
- 모바일에서도 핵심 값과 주의문이 잘리지 않아야 한다.

## 10. 오류·보안·운영 요구사항

- `DATA_GO_KR_SERVICE_KEY`는 서버 환경변수로만 읽고 저장소, API 응답, 브라우저, 로그에 노출하지 않는다.
- Encoding/Decoding 키를 안전하게 정규화하며 이중 URL 인코딩을 방지한다.
- 연결·응답 제한시간을 적용하고 연속 실패 시 회로 차단기로 외부 장애를 격리한다.
- 외부 API 실패 시 저장된 마지막 성공 데이터를 기준일과 함께 보여 주거나 `일시적으로 확인할 수 없음`을 표시한다.
- 외부 API 오류로 매물·고객·거래 API 전체가 실패해서는 안 된다.
- 데이터셋별 호출 제한, 이용조건, 재배포 가능 범위를 운영 전 확인한다.
- 고객 개인정보는 공공 API 요청 파라미터와 수집 로그에 포함하지 않는다.
- 수집 실행과 매물-공공데이터 수동 연결 변경은 감사 기록에 남긴다.

## 11. 성공 지표

출시 후 첫 4주 기준 목표는 다음과 같다.

| 지표 | 목표 |
|---|---:|
| 주소·단지명이 입력된 아파트 매물 중 실거래 근거 연결률 | 85% 이상 |
| 연결 가능한 매물의 K-apt 또는 건축물대장 정보 보강률 | 80% 이상 |
| 예약 수집 작업 성공률 | 98% 이상 |
| 공공데이터 때문에 핵심 업무 API가 실패한 비율 | 0% |
| 비교표 작성 시 외부 사이트 수동 조회 횟수 | 기존 대비 50% 감소 |
| 승인된 비교표 중 공공데이터 출처가 포함된 비율 | 70% 이상 |

정확한 연결률은 자동 연결과 중개사 확인 연결을 분리해 측정한다.

- 연결률의 분모는 주소와 단지명이 모두 입력된 활성 아파트 매물로 정의한다.
- 수집 성공률의 분모는 실행된 동기화 작업이며, 기관 장애를 제외한 수치와 포함한 수치를 함께 기록한다.
- 수동 조회 감소율은 출시 전 1주 동안의 중개사 자체 기록을 기준선으로 삼고 출시 후 같은 방식으로 비교한다.

## 13. 수용 기준

### 공통

- [ ] 실제 서비스키를 저장소에 넣지 않고 모든 대상 API를 호출할 수 있다.
- [ ] 인증 오류, 호출 제한, 시간초과, 비정상 XML·JSON을 사용자 친화적 오류로 처리한다.
- [ ] 데이터셋별 마지막 성공 시각과 출처를 확인할 수 있다.
- [ ] 외부 API를 차단해도 매물·고객·거래 기능이 정상 동작한다.

### 매매·전월세

- [ ] 지정 지역·월의 모든 페이지를 수집하고 재실행 시 중복이 생기지 않는다.
- [ ] 해제된 매매 거래가 유효 거래 통계에서 제외된다.
- [ ] 전세와 월세 통계를 분리한다.
- [ ] 매물 상세와 비교표의 거래 사례가 단지·면적·기간 기준을 표시한다.

### K-apt·건축물대장·지하철

- [ ] 후보가 복수인 경우 자동 확정하지 않는다.
- [ ] 중개사가 선택한 연결 대상을 변경하거나 해제할 수 있다.
- [ ] 원천값과 중개사 입력값이 다를 때 자동 덮어쓰지 않는다.
- [ ] 고객 자료에 포함된 값은 출처와 조회 기준일을 가진다.

### 고객 자료

- [ ] 승인본은 이후 데이터 갱신으로 자동 변경되지 않는다.
- [ ] 실거래와 호가, 공공데이터와 현장 확인의 차이를 설명하는 주의문이 포함된다.
- [ ] 연결이 불확실한 정보는 본문 사실로 단정하지 않고 확인할 사항으로 분리된다.

## 15. 미결정 사항

구현 착수 전에 제품 책임자가 다음을 확정한다.

1. 초기 서비스 지역을 기존 4개 구로 제한할지 전국 법정동 코드로 확장할지
2. 매매·전월세 기본 비교 기간을 12개월로 할지, 지역별 거래량에 따라 다르게 할지
3. K-apt·건축물대장 정보 중 고객 비교표에 기본 노출할 필드
4. 건축물대장 재조회 주기와 고객 자료 생성 전 강제 갱신 여부
5. 지하철 출구·편의시설 정보를 고객 매칭 점수에 반영할지 참고정보로만 둘지
6. 공공데이터 자동 연결을 관리자가 일괄 승인할지 중개사별로 확인할지
