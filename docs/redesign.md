# 중개메이트 재설계안 v0.3 (초안)

> 클릭 시안: `docs/prototype/index.html` (가짜 데이터, 백엔드 없음)

## 0. 전제 (사용자 결정, 2026-10-30)

- **사용자:** 여러 중개사가 매물과 고객을 **함께 보는 사무소**
- **고객 전달물:** 인쇄물, PDF/링크 공유
- **최우선 화면:** 지도에서 **내 매물**을 확인하고, 매물마다 **고객과의 거래가 어느 단계인지**(성사 여부 포함) 한눈에 보기

## 1. 무엇이 잘못됐었나

기존 "상담 작업대"는 시스템 처리 순서(검색→비교→근거→초안→승인)를 그대로 화면에 옮겼습니다. 그래서 중개사가 **무엇을 끝낼 수 있는지**가 보이지 않았습니다.
재설계에서는 중개사가 이미 쓰는 대상인 **매물 · 고객 · 거래 · 고객 자료**로 화면을 나눕니다.

## 2. 중심 개념: 거래 건 (매물 × 고객 × 단계)

한 매물에는 여러 고객이 붙고, 한 고객도 여러 매물을 봅니다. 그 연결 하나하나가 **거래 건**이며, 진행 단계를 가집니다.

| 단계 | 의미 | 넘어가는 기준 (예) |
|---|---|---|
| 소개 | 고객에게 매물 소개, 관심 표시 | 매물을 고객에게 연결 |
| 방문 | 현장 방문 예약·완료 | 방문 일정 확정 |
| 협의 | 가격·조건 협의 | 고객이 구체적 가격 제시 |
| 계약 | 계약서 작성, 계약금 지급 | 계약일 기록 |
| 완료 | 잔금·인도 완료 | 잔금일 기록 → 매물 **거래 완료** |
| 무산 | 진행 중단 (사유 기록) | 언제든 |

**매물의 지도 표시 상태** = 그 매물에 걸린 거래 중 가장 많이 진행된 단계입니다. 거래가 없으면 **거래 가능**으로 표시합니다.

## 3. 화면 구조

| 메뉴 | 핵심 질문 | 주요 동작 |
|---|---|---|
| **매물 지도** (첫 화면) | 내 매물은 어디 있고, 각각 거래가 어디까지 왔나? | 단계별 색 핀, 내 매물/사무소 전체 전환, 단계 필터, 핀 클릭 시 좌측에 매물 상세와 걸린 고객별 진행 단계 표시, 단계 변경 |
| **거래 현황** | 지금 진행 중인 거래는 무엇이고 다음에 할 일은? | 단계별 칸반 보드, 내 거래/전체, 카드 이동 |
| **고객** | 이 고객은 무엇을 원하고 어디까지 진행됐나? | 조건, 진행 중 거래, 고객 자료, 상담 기록, [맞는 매물 지도에서 보기] [비교 자료 만들기] [질문 답변 만들기] |
| **고객 자료** (고객 안) | 고객에게 무엇을 보냈나? | A4 미리보기, 근거, 검토·승인, **인쇄/PDF**, **링크 공유**(승인본만, 만료일 있음) |

| **자료실** | 이 내용의 근거가 되는 조항은? | 법령·공식 정책·사무소 문서·기사 검색, 원문 조각 확인, 고객 문의 답변에 인용, (관리자) 문서 등록 |

AI는 별도 메뉴도, 화면의 딱지도 아닙니다. 업무 화면 안에서 **관련 조항을 찾아 붙이는 기능**으로만 드러납니다.

### 3-1. RAG(문서 근거 검색)를 쓰는 곳

| 위치 | 검색 질의(자동) | 화면에 보이는 것 | 기존 엔진 재사용 |
|---|---|---|---|
| **매물 상세 › 확인할 사항** | 매물의 가격·지역·**거래 단계** (예: 9억 이하 → 생애최초 기준, 계약 단계 → 거래 신고 의무) | 체크리스트 항목마다 "출처: 법령 · 부동산 거래신고법 제3조" | `rag.search` + 근거 게이트 (불일치·시행 전 표시) |
| **고객 자료 › 중개사 의견·문의 답변** | 고객 조건·선택 매물·문의 내용 | 문장 끝 각주 번호, 문서 끝 출처 목록, 근거 없는 내용은 "추가로 확인할 사항"으로 분리 | `/advise`, `/ask` 초안 생성 + 인용 검증 |
| **자료실** | 중개사가 직접 입력 | 원문 조각, 발행 기관, 기준일, 위치(조·쪽), 내용이 다른 자료 연결 | `GET /api/evidence/search`, 문서 등록 API |
| **출처 패널** | (위 세 곳의 출처 클릭) | 원문 조각·기준일. 기사는 "보조 자료" 표시 | `GET /api/evidence/{id}` |

구조화 데이터(매물·실거래가)는 RAG가 아니라 SQL로 조회하고, 같은 출처 표시 방식으로 보여 줍니다.

### 3-2. 화면 원칙 (AI 도구처럼 보이지 않게)

- 사무용 프로그램 톤: 평면, 표 중심, 각진 모서리, 강조색 하나(남색). 그림자·그라데이션·알약 모양 배지를 쓰지 않습니다.
- "AI 초안", "근거 확인" 같은 딱지를 달지 않습니다. 고객 자료는 **중개사가 쓴 문서 형식**(본문, 각주, 출처 목록)으로 보여 줍니다.
- 설명 문구를 줄이고, 버튼은 동사형 업무 용어로 씁니다 (비교표 작성, 검토 요청, 링크로 보내기).
- 상태는 색과 글자로 함께 표시합니다 (색만으로 구분하지 않음).

## 4. 대표 시나리오

1. **아침 확인:** 지도를 열면 내 매물이 단계 색으로 보입니다. 상단 요약 "협의 2 · 계약 1"을 누르면 해당 매물만 남습니다.
2. **방문 후 기록:** 핀 → 좌측 상세 → 김하늘 고객 행에서 "다음 단계" → 협의로 바뀌고 핀 색도 바뀝니다.
3. **새 고객 매칭:** 고객 화면에서 [맞는 매물 지도에서 보기] → 조건에 맞는 핀만 강조됩니다. 상세에서 [고객 연결]을 누르면 소개 단계 거래가 생깁니다.
4. **자료 전달:** 고객 화면에서 [비교표 작성] → 비교표와 중개사 의견 초안(각주 출처) → 문서에서 직접 고친 뒤 검토·승인 → 인쇄 또는 링크로 보내기.
6. **계약 진행 중 확인:** 매물을 계약 단계로 옮기면 확인할 사항 맨 위에 "계약일부터 30일 이내 거래 신고"가 근거 조문과 함께 붙습니다.
7. **고객 문의 응대:** 자료실에서 "생애최초"를 검색 → 공식 안내와 기사 내용이 다르다는 표시 확인 → [고객 문의 답변에 인용].
5. **동료 매물 확인:** "사무소 전체"로 바꾸면 동료 매물도 흐리게 보이고, 담당자 이니셜이 표시됩니다.

## 5. 데이터 모델 변경 (시안 확정 후 진행)

| 기존 | 변경 |
|---|---|
| `listings` | `agent_id`(담당 중개사) 추가. 상태는 거래 건에서 계산 |
| `consultations` | **`customers`**(고객, `agent_id`) + **`activities`**(상담 기록 타임라인) |
| `consultation_candidates` | **`deals`**(listing_id, customer_id, agent_id, stage, next_action, dropped_reason) + **`deal_events`**(단계 변경 이력) |
| `drafts` | **`reports`**(customer_id, kind=비교표/질문 답변, 상태: 초안→검토→승인→전달) + `share_token`, `share_expires_at`, 열람 기록 |

근거 검색(RAG), 근거 게이트, 감사 기록, tenant 분리는 그대로 유지합니다.
